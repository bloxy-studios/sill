# Funding

**Current state (2026-08-21): Sill has no funding.** No sponsors, no grants,
no fiscal host, no donation accounts. The `.github/FUNDING.yml` file is
deliberately inert until a real account exists — this project does not ship
placeholder usernames.

## Philosophy (binding)

- Funding **sustains development**; it never buys influence. Technical and
  security decisions are unaffected by who pays
  ([SPONSORSHIP.md](SPONSORSHIP.md) is the enforceable version).
- Sponsors receive recognition and a healthier project — not ownership,
  roadmap control, or security priority.
- One honest funding rail beats five empty buttons. Donation-platform
  stacking on a pre-release repo reads as fundraising before delivery, and
  Sill won't do it.

## What funding would be used for

In priority order, with estimates, in
[oss/FUNDING_PLAN.md](oss/FUNDING_PLAN.md): code-signing certificates
(macOS notarization, Windows Authenticode), cross-platform test hardware,
maintainer development time on the public roadmap, security response
capacity, infrastructure margin.

## Plan (sequenced, from researched facts)

1. **Eligibility check first:** GitHub Sponsors requires residency in a
   supported region (and matching bank region) — the maintainer confirms
   this against the live list before setup. This one fact also gates the
   GitHub Secure Open Source Fund later.
2. **GitHub Sponsors** as the single rail once eligible: profile, tiers,
   2FA, payout — then `.github/FUNDING.yml` gets its one real line.
   (Decide bank-vs-fiscal-host _before_ setup; switching later requires
   GitHub Support.)
3. **Fiscal hosting (Open Source Collective)** only when there's a concrete
   trigger: a company that must invoice-pay, or a second contributor to
   reimburse.
4. **Grants**: researched landscape in [oss/PROGRAM_MATRIX.md](oss/PROGRAM_MATRIX.md)
   (17 programs, verified 2026-08-21). Honest conclusion recorded there:
   nothing is worth applying to pre-evidence; the strongest future fit is
   GitHub's Secure Open Source Fund once Sill has releases and users.

## Transparency commitment

If money ever arrives: totals received and high-level allocation
(development / security / infrastructure / hardware) get published
periodically in [evidence/](evidence/); individual private financial detail
does not. Sponsorship recognition follows [SPONSORSHIP.md](SPONSORSHIP.md).

## Sponsorship tiers (drafted now, activated with Sponsors)

Indicative shape, to be priced at setup: a thanks-tier (name in SPONSORS
list), a supporter tier (name in release notes for the period), and a
corporate tier (logo placement per SPONSORSHIP.md). No tier will ever offer
features, priority fixes, or security advantages — those aren't for sale.
