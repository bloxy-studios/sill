# GitHub Sponsors

Status: CURRENT (Last verified: 2026-08-21)

## Program

GitHub's native recurring/one-time donation rail for individuals and organizations. It is a payment platform, not a grant program: there is no selection committee and no award decision. Income is a function of audience size and corporate goodwill. The GitHub Sponsors Matching Fund is closed to new applicants (deadline was 2020-01-01).

## Official URL

https://docs.github.com/en/sponsors/getting-started-with-github-sponsors/about-github-sponsors

## What it funds

Nothing directly. It routes money from sponsors to maintainers. Also used as the disbursement rail for other GitHub programs (e.g. the Secure Open Source Fund pays through it).

## Eligibility

- Anyone who contributes to an open source project and lives in a supported region. Contributions counted broadly: code, docs, bug reports, triage, design, mentorship, project management.
- Organizations: must legally operate in a supported region.
- Must be 18+ (13-17 possible if Stripe can verify a legal guardian).
- 2FA must be enabled on the GitHub account.
- To receive bank payouts, region of residence and region of bank account must match. Otherwise a fiscal host must be used.
- Supported-region list is long (US, UK, Canada, most of EU, India, Japan, Australia, Brazil, Nigeria, Kenya, and many others) but not universal. CONFIRM the maintainer's country against the list on the official page.

## Typical funding

UNKNOWN — entirely demand-driven. No floor, no ceiling, no stated ranges. Do not project revenue.

## Application requirements

Not an application. Setup steps: join at github.com/sponsors, complete contact info, choose payout via bank account or fiscal host, create sponsorship tiers, submit bank and tax information, enable 2FA. GitHub reviews and accepts accounts into the program.

## Sill fit

MEDIUM (as infrastructure, not as revenue). Setting this up costs a few hours and unlocks eligibility for other programs that pay through Sponsors — that is the actual reason to do it now. Expect roughly zero income at pre-alpha with zero users. Treat it as plumbing, not funding.

## Missing evidence

- Confirm maintainer's country of residence is on the supported-region list.
- Decide payout target: personal bank account vs fiscal host (see Open Source Collective).
- Tax/bank details ready; 2FA enabled.
- A profile that describes what Sill is, since the profile is what other programs read.

## Application strategy

Set up the personal account now, before there is anything to fund. Add `.github/FUNDING.yml` to the Sill repo pointing at it. Do not create an organization sponsor profile until there is an org with more than one person in it. Revisit tiers only once there are users.

## Deadline

None — rolling, always open.
