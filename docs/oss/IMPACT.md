# Impact (Potential, Calibrated)

_Every claim here is a hypothesis until [../evidence/IMPACT.md](../evidence/IMPACT.md)
says otherwise. Applications must quote this file's claims at their stated
strength, not stronger._

## Potential impact, if the roadmap ships and earns adoption

1. **Developer time in agent workflows.** Parallel agents that block on
   unnoticed questions waste wall-clock hours; a terminal that routes
   attention could recover much of that. (Hypothesis; measurable via
   benchmarks + user studies only after Phase 4.)
2. **A neutral integration layer for the agent ecosystem.** A permissively
   licensed, vendor-neutral protocol surface for agent↔terminal interop
   would let every agent CLI improve UX once instead of per-terminal — and
   is adoptable by other terminals precisely because it's MIT/Apache and not
   attached to a vendor's platform. This is the largest potential ecosystem
   effect and the least certain.
3. **Permissive-license option in a copyleft category.** Users and
   redistributors who cannot adopt AGPL/GPL tooling currently have no
   agent-aware terminal option; Sill would be one.
4. **Lower-resource computing.** Published memory/CPU budgets, if met, make
   heavy multi-session workflows viable on modest hardware. (Budgets exist;
   numbers don't yet.)

## Impact measurement framework

Baseline recorded at zero (2026-08 snapshot). Tracked: contributors and
retention, release downloads, verifiable third-party integrations, protocol
adoptions (if L2/MCP ships), benchmark results, security response record.
Sources and calibration rules: [../evidence/METRICS.md](../evidence/METRICS.md),
[../evidence/ADOPTION.md](../evidence/ADOPTION.md).

## What is not claimed

No social-impact inflation, no productivity percentages, no "democratizing"
language. A terminal is developer infrastructure; its honest best case is
making skilled people measurably less interrupted and giving an emerging
ecosystem a neutral seam. That is enough to be worth building.
