# Sustainability (Application Summary)

_Canonical document: [../SUSTAINABILITY.md](../SUSTAINABILITY.md)._

**Current inputs:** one maintainer's unpaid time. **Current funding:** none.
**Runway risk:** the honest one — maintainer time and attention, documented
with mitigations in [../BUS_FACTOR.md](../BUS_FACTOR.md).

**Sustainability design, in order of activation:**

1. **Knowledge sustainability (active now):** decisions, processes, and
   architecture written down (ADRs, runbooks, threat model) so the project
   survives attention gaps and can absorb new maintainers cheaply.
2. **Scope discipline (active now):** versioned non-goals; a small surface
   one person can keep healthy beats a large one nobody can.
3. **Community (next):** contributor ladder toward bus factor ≥ 2 — the
   cheapest real sustainability investment.
4. **Money (deliberately sequenced):** GitHub Sponsors as infrastructure once
   eligible; targeted grants only after evidence exists (per
   [PROGRAM_MATRIX.md](PROGRAM_MATRIX.md) research, applying pre-evidence
   burns credibility); corporate sponsorship with influence firewalled
   ([../SPONSORSHIP.md](../SPONSORSHIP.md)); optional commercial services
   _adjacent to_ (never carved out of) the open core, only if warranted.
   First uses of any money are named in [FUNDING_PLAN.md](FUNDING_PLAN.md):
   signing certificates, test hardware, maintainer time.
5. **Exit honesty:** if development stalls, the status file says so and the
   permissive license guarantees continuation rights to anyone. Failure mode
   is loss of momentum, never user lock-in.
