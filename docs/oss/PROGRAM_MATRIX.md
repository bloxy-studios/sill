## Recommended sequencing

The honest summary: **there is nothing to apply to today.** Every competitive program on this list rewards either demonstrated adoption or demonstrated criticality, and Sill has neither. The work available right now is infrastructure setup, not applications.

### Phase 0 — now (infrastructure, not competition)

These are not grants. Nobody reviews them, nobody rejects them, and they cost hours rather than weeks.

1. **Confirm the maintainer's country of residence** against the GitHub Sponsors supported-region list. This single fact gates GitHub Sponsors and, through it, the GitHub Secure Open Source Fund.
2. **Confirm whether the maintainer is a German tax resident.** If yes, the Prototype Fund window (2026-10-01 to 2026-11-30) is the one genuinely stage-appropriate grant on this list and should be planned for immediately. If no, mark it permanently N/A.
3. **Set up GitHub Sponsors** on the personal account with bank payout. Add a one-line `.github/FUNDING.yml`.
4. **Add an OSI-approved licence, SECURITY.md, and an honest README.** Reviewers read repos.

### Phase 1 — after the first working release with users

5. **FUTO microgrant** — one short email to grantapps@futo.org. Low cost, low probability, on-thesis.
6. **Cline OSS Grant** — a short form; credits not cash, so treat as a cost offset only.

### Phase 2 — after real adoption and a genuine security surface

7. **GitHub Secure Open Source Fund** — the strongest long-term cash fit on this list. A terminal that executes agent output and holds credentials has a real security story once it exists. Rolling intake means there is no rush and no penalty for waiting.
8. **Open Source Collective fiscal hosting** — trigger is a company wanting to invoice-pay, or a second person to reimburse. Note: switching the Sponsors payout to a fiscal host later requires contacting GitHub Support.

### Phase 3 — only if the project's shape changes

9. **NLnet** — plausible only if a discrete, reusable technical work package can be defined and the call scope fits. Watch the Open Internet Stack call scope published 2026-09-03; do not apply in this round.
10. **goose grants** — only as a scoped goose-integration proposal, never as a pitch for Sill overall.
11. **Sovereign Tech Agency** — only for a spun-out infrastructure component with downstream dependents. Sill-as-a-product will always be screened out as a "user-facing application".
12. **GSoC** — reclassify as contributor recruitment, not funding. Needs 18 months of history and 5+ active community members first.

### Permanently closed or out of scope

Rust Foundation Maintainers Fund (funds the Rust Project, not projects written in Rust), Alpha-Omega (supply-chain-critical infrastructure only), Mozilla MOSS and Technology Fund (nothing open), Google Season of Docs (program concluded), GitHub Accelerator (no round since 2024), thanks.dev and Tidelift (a desktop app never appears in a dependency scan).

### Two things to avoid

- **Applying early.** A rejection is a wasted first impression with a funder that may be a good fit in two years. Nothing on this list has a scarcity dynamic that punishes waiting; most are rolling.
- **Stacking donation platforms.** Multiple funding buttons on a repo with no releases reads as fundraising before delivery. One rail (GitHub Sponsors) is correct until there are users.
