# Community

**Honest baseline (2026-08):** Sill's community is currently one maintainer.
This document is the plan for growing one deliberately, and the promises made
to people who show up early. It contains no claims of an existing community.

## Contributor journey

1. **User / lurker** — reads the roadmap, tries builds once they exist.
   Watching quietly is fine.
2. **First contribution** — a `good first issue`, a docs fix, a bug repro.
   Promise: a real review with pointers, not a drive-by "needs work"; the
   [quickstart](CONTRIBUTOR_QUICKSTART.md) is maintained so setup never
   burns your evening.
3. **Regular contributor** — repeated quality PRs. Promise: credited in
   release notes, consulted on changes in areas you've worked.
4. **Reviewer** — trusted judgment in an area; opinions explicitly weighed.
5. **Maintainer** — see [GOVERNANCE.md](../GOVERNANCE.md) and
   [MAINTAINERS.md](../MAINTAINERS.md). Earned, invited, never automatic.

No timelines attached — trust doesn't have a sprint cadence.

## Where things happen

| Venue              | Purpose                                                             |
| ------------------ | ------------------------------------------------------------------- |
| GitHub Issues      | Actionable bugs and accepted work ([triage guide](ISSUE_TRIAGE.md)) |
| GitHub Discussions | Everything else — see categories below                              |
| Pull requests      | Code review ([review guide](PR_REVIEW.md))                          |

No Discord/Matrix yet, deliberately: a chat server with three people in it is
worse than none, and asynchronous, searchable discussion suits a solo-
maintained project. Revisit when there are regulars to fill it.

### Discussion categories (kept minimal)

- **Announcements** (maintainer posts, releases)
- **Ideas** (pre-issue feature thinking, RFC incubation)
- **Q&A** (help; answerable questions)
- **Development** (architecture, design threads)
- **Show and Tell** (things built with/around Sill — will be empty until it isn't; that's fine)

Agent-integration topics live in **Development**/**Ideas** until volume
justifies a dedicated category. Roadmap discussion happens on the roadmap's
issues/RFCs rather than a separate category.

## Norms

The [Code of Conduct](../CODE_OF_CONDUCT.md) governs. Local additions:

- Blunt about code, kind to people. Both halves matter.
- Reproduction steps and version info are how you show respect for volunteer
  time.
- Drive-by demands ("when will X ship?") get a link to the roadmap — energy
  goes to people who engage.
- Large ideas start as Discussions/RFCs, not 4,000-line surprise PRs
  ([large-change policy](../CONTRIBUTING.md#large-changes)).
- Security suspicions go private first ([SECURITY.md](../SECURITY.md)).

## Measuring (without gaming)

Community health indicators tracked in [evidence/](evidence/): contributors,
first-time contributors, PR/issue response times, discussion activity.
Metrics are evidence of health, not targets to inflate —
no star-farming, no fake activity, ever.
