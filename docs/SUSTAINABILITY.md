# Sustainability

How Sill intends to still exist in five years. Current inputs: one
maintainer's unpaid time. Current money: none. The plan below is about
converting _usefulness_ into _durability_ without corrupting the project.

## Principles

1. **The open-source project is the product, not the funnel.** Core Sill —
   terminal, workspaces, agent interop — stays MIT OR Apache-2.0 and genuinely
   complete. No artificial ceilings designed to sell relief from them.
2. **No single-source dependency.** No one funding source should be able to
   kill or steer the project by leaving. Diversify small rather than depend
   big.
3. **Money buys time, not influence** ([SPONSORSHIP.md](SPONSORSHIP.md)).
4. **Survivability floor:** everything needed to fork and continue is public
   ([BUS_FACTOR.md](BUS_FACTOR.md)). Sustainability failure would mean loss of
   momentum, not user lock-in.

What maintainer time actually costs — and what funding would buy first
(signing certificates, test hardware, security response time) — is itemized

## Sustainability beyond money

- **Knowledge**: decisions and processes written down (ADRs, runbooks) so the
  project survives its maintainer's absence
- **People**: contributor ladder ([COMMUNITY.md](COMMUNITY.md)) toward bus
  factor ≥ 2 — the cheapest sustainability investment available
- **Scope discipline**: the roadmap's non-goals are a sustainability feature;
  small surface area is what one maintainer can keep healthy

## Failure honesty

If development stalls, [PROJECT_STATUS.md](PROJECT_STATUS.md) will say so
plainly rather than letting the repo rot ambiguously. Archiving with a clear
README beats a zombie project.
